# Spec: Close CI gaps (ROADMAP 3.5–3.7)

## Goal

Close the three remaining Phase-3 CI gaps so that frontend breakage, Python style/lint
errors, and eval-trend loss are caught in CI rather than locally (or not at all):

- **3.5** — Web lint + build gate on PR (`npm run lint && npm run build`).
- **3.6** — Ruff lint gate for the API (`ruff check .`).
- **3.7** — Persist the market-definition benchmark summary as a CI artifact.

Out of scope: adding frontend unit/e2e tests (none exist today; `next build` runs `tsc`
and is the type gate), pip/npm dependency caching, deploy workflows (Phase 6), and the
nightly drift job (8.3). Each is noted under "Is CI complete after this?" but not built here.

## Approach

### 3.5 — Web lint + build (`web-ci.yml`, new)

New workflow `.github/workflows/web-ci.yml`, path-filtered on `apps/web/**`, mirroring the
structure of `data-contracts.yml` but for Node. One job, `working-directory: apps/web`:

1. `actions/setup-node@v4` with `node-version: "20"` (matches `apps/web/Dockerfile`) and
   `cache: npm` keyed on `apps/web/package-lock.json`.
2. `npm ci` (lockfile present and committed).
3. `npm run lint`.
4. `npm run build`.

`next build` needs no live API: `NEXT_PUBLIC_API_URL` has a localhost default in
`next.config.mjs`, and pages are not statically fetched at build time. No env/secrets needed.

**Baseline fix required in the same PR.** `apps/web` has **no ESLint config** (no
`.eslintrc*`, no `eslint.config.*`, no `eslintConfig` key in `package.json`), though
`eslint` and `eslint-config-next` are installed. In that state `next lint` prompts
interactively to scaffold a config, which hangs/fails under CI. Add
`apps/web/.eslintrc.json`:

```json
{
  "extends": "next/core-web-vitals",
  "plugins": ["@typescript-eslint"]
}
```

`next/core-web-vitals` is the config `next lint` would otherwise scaffold. The
`@typescript-eslint` plugin must be registered explicitly: the codebase already carries
`// eslint-disable-next-line @typescript-eslint/no-explicit-any` directives (in
`GraphView.tsx`), and without the plugin in `plugins` those directives error with
"Definition for rule … was not found". Registering the plugin (rules left at their
default *off*) makes the directives resolve without enabling any new rule project-wide —
the `as any` casts stay as-is. The plugin is already an installed transitive dep of
`eslint-config-next`.

After the config lands, run `npm run lint` locally and resolve findings so the gate is
green on first CI run (same "baseline must land with the gate" discipline as the
`pdf_url` fix in 3.3). The current tree has two real findings to fix:
`react/no-unescaped-entities` in `indexed-cases/[case_id]/page.tsx` (an apostrophe) and
`JurisdictionChat.tsx` (quote marks) — escaped with `&apos;` / `&quot;`.

### 3.6 — Ruff lint gate (`api-ci.yml`)

Add a separate `lint` job to `api-ci.yml` (parallel to `test`, same Python-3.10 venv
install pattern) running:

```
.venv/bin/ruff check .
```

A separate job — not an extra step on `test` — keeps a lint failure visually distinct from
a test failure and lets them run concurrently. `ruff==0.6.9` is already pinned in
`requirements.txt`; no new dependency. The job installs the full `requirements.txt` (same
pattern as `test`) rather than `pip install ruff==0.6.9` — slower, but keeps the pinned
ruff version single-sourced in `requirements.txt` instead of duplicated in the workflow.

**Baseline fix required in the same PR.** `ruff check .` currently reports **235 errors**,
so a hard gate would fail immediately on merge. Breakdown:

| Rule | Count | Nature |
|------|-------|--------|
| F401 | 134 | Unused imports — auto-fixable |
| E402 | 52 | Module import not at top — the deliberate `sys.path.insert(...)` then import pattern used across `scripts/` |
| F541 | 22 | f-string with no placeholders — auto-fixable |
| F841 | 13 | Unused local — mostly auto-fixable |
| E401/E702/E811/E741/E731 | 14 | Misc — manual |

161 of 235 are auto-fixable. Plan, all in this PR:

1. Add a minimal `[tool.ruff]` block to `apps/api/pyproject.toml` (create the file if
   absent — the API has no ruff config today, which is why local runs use defaults). Add
   `per-file-ignores` for both `"scripts/**" = ["E402"]` and `"tests/**" = ["E402"]` — the
   intentional `sys.path` bootstrap pattern (insert path, then import `app.*`) appears in
   both trees, so both need the exemption. This alone clears all 52 E402s. No `line-length`
   is set: ruff's default rule set does not select E501 (line-too-long), so line length is
   never checked and configuring it would be dead config.
2. `ruff check --fix .` to clear the ~161 auto-fixable findings (F401/F541/F841).
3. Manually resolve the small remainder (E401/E702/E741/E731/F811 and any non-auto F841,
   e.g. the unused `writer` in `tests/test_source_integrity.py:50`).
4. Confirm `ruff check .` exits 0 before raising the PR.

> Decision point for review: whether to fix the codebase to satisfy default ruff, or to
> widen `pyproject.toml` ignores to grandfather some rules. Recommendation: fix (the
> auto-fixable bulk is free and unused imports are real noise); only ignore E402 in
> `scripts/` where the violation is structurally required, not sloppiness.

### 3.7 — Benchmark artifacts (`api-ci.yml`)

`api-ci.yml`'s "Run market-definition benchmark" step already writes
`/tmp/benchmark.market_definition.ci.summary.json` and `.summary.md`. Add one step after it
in the `test` job:

```yaml
      - name: Upload benchmark summary
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: benchmark-market-definition-ci
          path: |
            /tmp/benchmark.market_definition.ci.summary.json
            /tmp/benchmark.market_definition.ci.summary.md
          retention-days: 90
```

`if: always()` so the summary is captured even when the benchmark step fails its threshold
(that is exactly the run you want to inspect). This only *persists* the trend; the
benchmark step itself remains the pass/fail gate. No regression-trend comparison is built
here.

## Workflow sketches

### `.github/workflows/web-ci.yml` (new)

```yaml
name: Web CI

on:
  pull_request:
    branches: [main]
    paths:
      - 'apps/web/**'

permissions:
  contents: read

jobs:
  lint-build:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    defaults:
      run:
        working-directory: apps/web
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: npm
          cache-dependency-path: apps/web/package-lock.json
      - name: Install dependencies
        run: npm ci
      - name: Lint
        run: npm run lint
      - name: Build
        run: npm run build
```

### `api-ci.yml` — additions (diff intent)

  test:

## Is CI complete after this? (robustness review)

Adding 3.5–3.7 closes the Phase-3 backlog: every code surface (API logic, API style,
frontend, data contracts, screening, eval baseline) now has a PR gate. CI is **functionally
complete for Phase 3**. Remaining robustness gaps, none of which Phase 3 commits to —
flagged so the decision is explicit:

- **A. `api-ci.yml` has no path filter.** It runs on every PR, including web-only and
  docs-only changes. Harmless (fast, deterministic) but wasteful. Optionally add
  `paths: ['apps/api/**', 'data/**']`. Deliberately left out here to avoid a green-check
  gap on required status checks; revisit if minutes become a concern.
- **B. `concurrency` cancellation — bundled into this PR.** Pushing twice to a PR would
  otherwise run both SHAs to completion. A `concurrency` block (`group:
  ${{ github.workflow }}-${{ github.ref }}`, `cancel-in-progress: true`) is added to the
  new `web-ci.yml` and to `api-ci.yml`. The two data workflows are left untouched for
  now (path-filtered and rarely double-pushed); add the same block there if it becomes a
  concern.
- **C. No dependency caching for Python.** Every API job rebuilds the venv (~tens of
  seconds). Acceptable now; `actions/cache` on pip is the optimisation when it bites.
- **D. Frontend has lint + build but no tests.** `next build` (which runs `tsc`) is the
  only behavioural gate. Matches ROADMAP intent (no frontend test row exists); note it so
  the absence is a choice, not an oversight.
- **E. Benchmark trend is stored, not asserted.** 3.7 persists the artifact; it does not
  compare run-over-run F1. The benchmark step's own threshold remains the gate. A trend
  regression check is a larger, separate piece of work (relates to 5.3/5.5).
- **F. No `ruff format --check`.** This spec gates lint only; the project does not adopt
  ruff's formatter. Out of scope.

Recommendation: ship 3.5–3.7 plus **B (concurrency)** as specced; leave A/C/D/E/F as
documented, deliberate non-goals for separate follow-up.

## Rollback

Each change is additive and isolated:
- Delete `web-ci.yml` / `.eslintrc.json` to drop the web gate.
- Revert the `lint` job and `pyproject.toml` ruff block to drop the ruff gate (the
  `ruff --fix` cleanup commits are independently revertable but harmless to keep).
- Remove the upload step to drop 3.7.
